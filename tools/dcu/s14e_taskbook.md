# S14e 任务书(Lead 预设;S14d 收口后立即派发)

## 要回答的唯一问题
**"graph 运行间不可复现"是 graph 的普遍性质,还是 S14c 那个省内存图配置(`PIECEWISE` + `capture-sizes 1 2 4 8`)特有的?**
—— 因为 S11m 当年在 **TP=2 / `maxlen 4096` / 默认 `FULL_AND_PIECEWISE` 51+2 桶** 下测到 **同 cache 热启动 3/3 逐位一致(0/512,Δlogprob 4.8e-5)**,与 S14d 的结论直接冲突。

## 已有事实(不要重测)
* **S14d(2026-10-10 02:33Z)**:TP=4 / maxlen 262144 / `PIECEWISE` + `1 2 4 8` / 8 GiB swap / swappiness 200 下,**两次 AOT 重载(同 cache、同 shape、`aot_load=4`)12/12 prompt 不逐位一致**;同上下文 `prompt_logprobs` max|Δ| **7.83–11.57 nat**、mean **1.01–1.51 nat**、argmax flips 7–31、差异覆盖 44–120 个位置;与"现场编译 vs 重载"同档 ⇒ **H-AOT 被否证**,因子是 graph 路径本身。
* **S11m**:`=1` / TP=2 / `maxlen 4096` / **默认图配置** 下 **热启动 3/3 逐位一致**(0/512)、冷编译 ≠ 自身重载(314–318/490)。
* **S14b**:eager 逐位可复现(1024 token Δ=0.000、8/8 flip Δ=0.000),且 eager 与 CPU 真值差 0.0025 nat。
* **S14c**:省内存图配置是**为压内存而引入**的(`PIECEWISE`+4 桶,默认 51+2 桶 ready 1645 s、余量仅 66 MB)。

## Lead 追加要求(2026-10-10T03:40Z;`send_message` 对 subagent 不可达,故落盘)
1. **批准协议修订**:按 **G1 → G2 → G5** 执行,**G3/G4 如实登记"未做 + 原因 + 既有同口径证据"**;成本数字要写清(默认图配置每次启动 ≈**1645 s**、两轮 capture ≈**1383–1395 s** ⇒ 单格三跑 ≈82 min)。
2. **G1 的两跑口径必须写死**:两跑都应是**真 AOT 重载**(逐次给 `Directly load AOT compilation from path` 与 cache key),并写明"复用了 S11m 预热的 cache、代码 vintage 与本步一致"及其校验方式——"cache 复用是否等价于本步自建"是这条结论的**唯一软肋**,必须有原文可查。
3. **G1 若不一致,不得直接下"graph 全配置不可复现"的结论**:至少要用**两种图配置**的对照支撑(例如 G2 的省内存配置再补第 3 跑);单点不一致不足以定性。

## 已知成本(影响裁剪,来自 S14e 中期)
* 默认图配置(`FULL_AND_PIECEWISE`,51 capture sizes + FULL)**每次启动两轮 capture ≈1383–1395 s**(≈26 min),cache 命中只省 ~90 s ⇒ 生产若选默认图配置,**启动时间要按 ~26 min 计**。
* `PIECEWISE` + `1 2 4 8` 的启动 ≈230–240 s ⇒ 这是"省内存图配置"的另一个好处(启动快 10×)。

### S14d 已给出的额外证据(2026-10-10,用于判定)
* 7 臂 / 21 对 / **252 个 prompt-pair 仅 6 个(2.4%)逐位一致**;21 对的 `mean|Δ|` 全部落在 **1.24–1.45 nat** 窄带、与配置正交。
* 关掉 `combo_kernels`/`benchmark_combo_kernel` **无收益**(1/36)⇒ S14b 的修法建议 #1 被否证。
* 差异**从 prompt 第 6–13 位就开始**(那是 prefill 走 `M>8` GEMM 的阶段)⇒ 若某格可复现,注意分歧起点位置本身也是线索。
* `TRITON_CACHE_DIR` 是**全步共用**的 `/mnt/game/triton-gfx906/cache`(1.9 GB)⇒ "每次 autotune 重抽"这条假设也已被削弱,但仍值得在 G1/G2 里留意。
**判定**:若 **G1 一致而 G2 不一致** ⇒ 结论=**"省内存图配置破坏了可复现性;默认图配置可复现"**,生产就必须在"内存"和"可复现"之间选,并给出两者的量化对比(默认图配置的内存代价:S14c C7 ready 1645 s / 余量 66 MB @16 GiB swap);
若 **G1 也不一致** ⇒ 结论=**graph 全配置不可复现**,生产只能用 **eager**(126.83 ms,慢 4.4%)或接受不可复现。
