# WP1.3 接受长度 vs 上下文扫描

> 施工依据：BUILD §5 WP1.3；设计依据：DESIGN §4/D4、PROJ §10.5
> 属主：A（Lead）。日期：2026-10-24。树 SHA `7078b5fe137feeab3750ee243daeaf172dc439d8`（分支 `dtk`）。
> 臂：eager（生产脚本）、MBT 8192、`max_num_seqs=4`、c=1、greedy、`max_tokens=96`、repeat 2。
> Prompt 源：**同一份真实文档** `docs/design/z100-dual-prefill-reconciliation-projection.md`，用 WP0.5 的
> `--prompt-file + --truncate-tokens` 精确截到 1024/2048/4096/7469 token（探针报告的 `tokens_actual` 与 server usage 一致）。

---

## 1. 一句话结论

**接受长度不是上下文长度的单调函数，而是"截断点内容"的函数**：同一文档在 1024/2048/4096/7469 token 处
acc = **4.80 / 2.29 / 3.00 / 2.67 tok/step**（非单调，跨度 2.1×）。
⇒ DESIGN/PROJ 里"长上下文接受长度 2.84 vs 短上下文 5.82 = 长度效应"的推断在本 prompt 上**不成立**；
7469 点与 B0 完全一致（2.667 = B0 的 2.667，差 0.000）说明探针口径正确；
**P3 的"接受长度修到 4.0"目标作废**（没有长度效应可修，只有换 prompt/文档或换 drafter 才可能改变）。

### 2.1 BUILD 判读的三个分支

BUILD WP1.3 的判据是"接受长度随长度单调下降 ⇒ 长度效应（LABD/P3 收益成立）"，否则是"内容效应，换文档再测；
仍如此 ⇒ 接受长度不是本工作负载的可优化项，P3 的 4.0 目标作废"。本数据：

1. **不单调**：1024 最高（4.80），2048 最低（2.29），4096 回到 3.00，7469 2.67 ⇒ 不是长度效应。
2. 在 1024 就已经是 4.80（远高于 2.8）⇒ 支持"内容效应"分支。
3. 7469 与 B0 完全一致 ⇒ 探针口径正确（BUILD 第三条判据）。
⇒ **结论：接受长度由内容决定，本工作负载没有"长度塌陷"可回收；P3/P3' 的接受长度目标作废。**
（这与 WP0.3 的纯 n-gram 上限 1.315 相互独立：一个说"换 drafter 的物理上限低"，一个说"现有 drafter 的 acc 波动来自内容"。）

## 4. 判读（对照 BUILD §5 WP1.3 阈值）

| 判据 | 结果 | 判定 |
|---|---|---|
| acc 随长度单调下降 ⇒ 长度效应 | 4.80 → 2.29 → 3.00 → 2.67，非单调 | **否** |
| 1024 已是 ~2.8 ⇒ 内容效应，换文档再测 | 1024 是 4.80（>2.8），且非单调 | 支持内容效应 |
| 7469 与 `b0-mbt8192-7469` 一致（±0.3） | 2.667 vs 2.667（±0.000） | **过** |
| 动作 | P3 接受长度 4.0 目标作废；LABD 收益预期不成立 | 按 BUILD 落 |

**注意**：本结论对**本 prompt 文档**成立。用户自己的 7469 文档若内容不同（代码/表格/重复模板多），acc 可能不同；
但"长度效应"这一机制在 4 个截断点上没有被观察到，因此不能再用"长上下文"解释 2.84 vs 5.82 的差异（PROJ §1 的 A2 问题已有答案：是内容/文档差异）。

## 5. 反证条件

- 若换 2–3 份不同文档（代码、小说、表格）重复本扫描，都出现"单调下降"，则本结论推翻——应重开长度效应假设。
- 若在 **graph 臂**上重扫（graph 的 acc 系统性更高，本报告 7469 处 2.909），趋势可能不同；但"是否单调"的判据与臂无关，需另行记录。
- 若 prefix cache 命中改变了生成路径导致 acc 漂移（本报告短截断点理论上会命中更长的前缀），需用不同文档逐点 cold 重测。
