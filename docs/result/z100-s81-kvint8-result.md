# S81 结果：int8 KV cache（sdot4 注意力）上生产

日期：2026-11-11。用户指示："还是把 sdot4 部署到生产"。
台账 `.s81/wp-s81.md`，原始数据 `runs/prefill-lctx/s81/`。

---

## 0. 三句话

1. **sdot4 上生产了**，但落地形态是 **int8 KV cache**
   （`--kv-cache-dtype int8_per_token_head` + `v_dot4` 注意力内环）：
   KV 显存减半，缓存容量 1.03M → **1.97M** token，262k 并发上限
   3.95× → **7.50×**。
2. **预填更快**：8k −14.3%、16k −7.1%、32k −2.8%、131k −0.9%。
   拆解后 KV 格式本身对预填几乎免费（≤1%），收益主要来自把
   MIN_CTX 从 8192 再降到 4096。
3. **代价两笔**：KV 量化是有损存储（logprob 最大偏 0.036 nat、0/96 token
   翻转）；decode c=2 的 TPOT **+5.3%**（c=1 −1.4%、c=4 −10%）。

---

## 1. 做了什么

S80 把 sdot4 内核修对了，但它是测试专用的独立 op，生产后端遇到
`int8_per_token_head` 直接抛 `NotImplementedError`。本轮补齐了整条链路：

| 改动 | 文件 |
|---|---|
| 内核改名 + 移交公共注册 | `csrc/rocm/attnd_inner_kvint8.hip`（新）、`ops.h`、`torch_bindings.cpp`、`CMakeLists.txt` |
| 放开 int8 KV 的上游拒绝 | `vllm/v1/attention/ops/triton_unified_attention.py` |
| Triton 内核加逐 tile int8 反量化分支（fallback） | 同上（2D/3D 两个内核） |
| 预填/解码各加 int8 HIP 内环分发 | 同上 |
| 生产开关 | `serve_deploy.sh`（`KV_DTYPE` + `MIN_CTX=4096`） |

`.so` = `.s81/rocm_c_release/_rocm_C.abi3.so`（md5 `b032e0cb`），
内核源 `attnd_inner_kvint8.hip`（md5 `ee50d99f`）；**原 fp16 内核
`csrc/rocm/attnd_inner.hip` 未动**（md5 `b93db390` 不变）。

回滚是分层的：`.so` 回旧版 → 自动退回 Triton 反量化路径；再摘
`KV_DTYPE` → 完全回 S80 形态；`MIN_CTX=8192` 可单独退门。

## 2. 数值

| 门 | 结果 |
|---|---|
| 内核 vs fp32 参考（真实页形 1616，ctx 4k/20k/131k，m 1/3/7488，segs 1/4，2 seed） | 36/36，相对误差 ≤1.7e-3，cos ≥0.999999 |
| block=832 页形（同一套用例） | 18/18 通过 |
| 新覆盖的 ctx 带（4096–8192）96 例角点 | **max\|d\| = 0（逐位相同）** |
| one-hot V 测 KL | 3.4e-5 ~ 6.7e-5（门 1e-2） |
| 服务级 logprob（fp16 KV 基线） | 96 位置 max\|d\|=0.036 nat，0 token 翻转 |

> **页形勘误**：立项时写的 "block_size=832" 是 fp16 KV 下的数字。切到
> int8 KV 后，平台为了让注意力页不小于 mamba 页，会把它抬到 **1616**
> （日志：`Setting attention block size to 1616 tokens ...`）。所以本轮
> 两种页形都做了门，生产实际跑的是 1616。

0.036 nat 是 int8 KV 存储本身的代价，不是内核问题——内核在同一份量化
K/V 上与 fp32 的差是 3e-4 量级。

## 3. 性能

### 3.1 预填 TTFT（新 seed，2 reps）

两个基线要分开看，否则会把噪声当成收益：

| 长度 | ① S80 生产（旧 .so, fp16 KV, 门 8192） | ② S81 .so + fp16 KV, 门 8192 | ③ S81 .so + fp16 KV, 门 4096 | ④ 采纳（int8 KV + 门 4096） |
|---:|---:|---:|---:|---:|
| 8192 | 9.04 s | 9.40 s | 8.01 s | **8.06 s** |
| 16384 | 18.83 s | 18.69 s | 17.35 s | **17.36 s** |
| 32768 | 41.13 s | 40.90 s | 39.49 s | **39.75 s** |
| 131072 | 274.63 s | — | — | **272.06 s** |

- **采纳 vs 当前生产（①→④）**：8k −10.8%、16k −7.8%、32k −3.3%、131k −0.9%；
- **门本身的贡献（②→③）**：−14.7% / −7.2% / −3.5%；
- **KV 格式本身的贡献（③→④）**：+0.6% / +0.0% / +0.7% → **预填上是零成本**。

①和②是同配置两次开机，差 4%，是启动间噪声——所以"KV 格式让预填变快"
这种说法不成立，收益几乎全部来自门 8192→4096。

### 3.2 decode TPOT（ms，p50）

| 并发 | fp16 KV（同 .so、同门） | int8 KV（采纳） | 变化 |
|---:|---:|---:|---:|
| 1 | 14.60 | 14.40 | −1.4% |
| 2 | 26.73 | 28.17 | **+5.4%**（8 轮复现，范围 28.07–28.20） |
| 4 | 58.54 | 52.70 | **−10.0%** |

c=2 的差距经隔离测试确认来自 KV 格式本身（相同配置换 Triton 解码仍
28.0 ms，且 c=4 更差 61.6 ms），与 HIP 内环无关；HIP 内环在 c=1/c=4
上是净收益。

|---|---:|---:|
| 缓存容量 | 1,034,190 token | **1,966,828 token** |
| 262k 并发上限 | 3.95× | **7.50×** |

## 4. 边界与后续

- 有损格式：本轮只验到 logprob / 贪心一致，未做下游任务效果评测；
- 只在 gfx906 / head 256 / GQA6 / block_size%16==0 上启用，其他形状自动
  退回 Triton 反量化；
- c=2 的 +5.4% 是已知回退，且已定位到 KV 格式本身。若 c=2 是主用途，
  摘掉 `KV_DTYPE` 即可（`.s81/state/RESTORE.sh kv`），4096 门的预填收益保留。
