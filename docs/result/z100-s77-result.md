## 一、结论（先看这段）

**注意力内核 131k 时间 −8.0%、吞吐 +8.7%（5.26→5.72 TF/s，同口径），
输出逐位不变；服务级 131k TTFT −4.6%～−5.9%、decode 每步 −3.7%，
全部可回滚。但没有达到设计图的算力门（6.0 TF/s / +15%）。**

1. **把 1.27× 缺口算清了。** 1113.9 ms 里，Q 行每 tile 重读占 262.9 ms、
   128 条 dot2 占 230 ms、softmax 只有 33.4 ms。Q 重读一项就等于整个
   缺口（145.5 ms）——设计图押对了。
2. **真正的改法不是设计图那两刀。** Q 搬到 LDS 反而慢 12%（1271 ms，
   与 S71 的 1260 ms 吻合）；拆链（2/4 链）全部 spill（2155–3228 ms）。
   **有效的是"一次 Q 读服务 32 个键"**：暂存从 16 键扩到 32 键，
   每 lane 两个 score，Q 全局读指令数减半，softmax 每 16 键顺序一字未改，
   所以逐位同。
3. **T2（12–22 TF/s）被算死了。** 把注意力点积成本整个抹成 0，这个内核
   也只剩 651 ms，而 T2 的门是 696 ms——**物理上不可达**。瓶颈不在点积，
   在 PV 的"每指令 2 FLOP"逐元素形态（本卡无 WMMA/MFMA）。
4. **增益随上下文深度单调增长**（131k 逐 chunk：2.7% → 6.6%），
   头和尾的 chunk 不动 —— 这正是"只快注意力、其他都不动"的证据。

## 三、缺口归因（WP0，131k，消融阶梯）

| 臂 | 内容 | ms | 归因 |
|---|---|---:|---|
| base | 生产内核 | 1113.9 | — |
| 删 QK 全部 load + 点积 | — | 572.1 | QK 段 541.8 ms（48.6%） |
| 点积只做 1/4 | — | 941.4 | **128 条 dot2 = 230 ms** |
| Q 换常量 | — | 851.0 | **Q 重读 = 262.9 ms（23.6%）** |
| 删 exp / 删蝶形 | — | 1109.7 / 1084.7 | softmax 只值 33.4 ms |

点积有效速率 = 3.66e11 次 dot2 / 230 ms = **6.37 TF/s**，正好是微内核
测出的"120 CTA 单链天花板 6.05"。所以 dot2 已经在单链极限上跑，
但拆链在本内核里被 LDS 读带宽和寄存器预算钉死（实测 4 条显式标量链
= 1564 ms，0.71×）。

## 四、采纳的形态

`csrc/rocm/attnd_inner.hip` 的候选替换（`.s77/arms/t1e.hip`，**尚未覆盖生产源**）：

1. **暂存 32 键**（K 16 KB + V 16 KB 单缓冲），仍是 32 KB/CTA；
2. **一次 Q 读两链**：lane 持 token t 与 t+16 两个 score，Q 全局读减半；
3. **暂存放到 compute 之后**，寄存器峰值 121 vgpr / spill 0
   （带预取的同形态必须 8 个 uint4 常驻 → vgpr 128 + spill，实测 1569 ms）。

softmax/PV 的每 16 键顺序一字未改 → 逐位同自动成立；每 32 键两个
barrier == 原来每 16 键一个。采纳步骤见 `.s77/state/APPLY.md`。

## 五、prefill 各阶段速度（最终在生产形态上实测，2026-11-10）

口径：`.s62/prefill_stages.py`，逐 iteration 引擎日志，冷缓存（每长度
每 rep 新 seed），2 rep 取 p50；服务为生产 argv/env + 日志 flag。

### 5.1 总表

| ctx | TTFT (s) | prefill steps | 引擎 tok/s | 客户端 tok/s |
|---:|---:|---:|---:|---:|
| 1024 | 1.22 | 1 | 855.2 | 841.4 |
| 4096 | 4.63 | 2 | 887.7 | 884.0 |
| 8192 | 9.71 | 2 | 846.1 | 843.9 |
| 16384 | 23.33 | 3 | 704.7 | 702.3 |
| 32768 | 46.23 | 6 | 709.7 | 708.8 |
| 65536 | 108.54 | 10 | 604.4 | 603.8 |
| 131072 | 293.30 | 19 | 447.2 | 446.9 |

### 5.2 逐 chunk 分解（ms / tokens）

- **1024**：1174 / 1024（单步）
- **4096**：2527 / 2496 → 2078 / 1600
- **8192**：7126 / 6656 → 2556 / 1536（全程 2D 路径，不做注意力内核）
- **16384**：8262 / 7488 → 12650 / 7488 → 2299 / 1408（首 chunk 2D，其后 3D）
- **32768**：8286 → 12657 → 9741 → 10573 → 2916 → 1991
- **65536**：8316 → 12686 → 9790 → 10617 → 12278 → 12785 → 14977 → 15017
  → 9106 → 3582
- **131072**：8387 → 12782 → 9760 → 10575 → 11671 → 12800 → 13863 →
  14962 → 16057 → 17153 → 18251 → 19347 → 20446 → 21542 → 22636 →
  23735 → 24829 → 9475 → 4806

### 5.3 读法（三句话）

1. **首 chunk 恒定 ~8.3 s**：权重 GEMM + AR + norm 等固定项，任何 ctx 都要付；
2. **深 ctx 的 chunk 逐级变贵**：131k 中间 chunk 到 24.8 s/chunk，注意力随
   KV 深度线性增长——这正是 S77 改的那一段；
3. **16k 门槛两侧仍无断崖**（16384 首 chunk 8262 ms vs 8192 全程 7126 ms），
   与 S68 结论一致，`MIN_CTX=16384` 的取值仍成立。

## 六、T2 否证（为什么 12 TF/s 在本形态不可达）

| 量 | ms |
|---|---:|
| 131k 生产 | 1113.9 |
| 删掉全部 QK（staging+softmax+PV 仍在） | **651.3** |
| T2 门（+60%） | 696 |
| 零 QK 成本的理论天花板 | 5.26 × 1113.9/651.3 = **9.00 TF/s** |

PV 是 256 条 `v_fma_mix_f32`/CTA-tile（S70 ISA 账 25.7%），每条 2 FLOP，
与 QK 共用 VALU 发射口。QK 再快也压不掉它；本卡无 WMMA/MFMA（S70 三证据），
所以"12–22 TF/s"需要换掉 PV 的逐元素形态，不在注意力内核内部可解。
**注意力算力议题闭案于 5.72 TF/s（T1），天花板 9.00 TF/s。**

## 八、口径对账：5.26 与 4.78、6.0 与 5.5

设计图对 T1 同时写了两套标准，且基线数字与本次不同源。逐条对齐：

### 8.1 基线

| 口径 | 131k TF/s | 来源 |
|---|---:|---|
| 设计图 in-vivo | 4.78 | S70 用逐 chunk live-tile 重算的 FLOPs 模型 |
| 本次 harness | **5.26** | `.s71/ab_arm.py` 统一的 FLOPs 公式，与 T1 同源 |

两者分子分母口径不同，**不能交叉相除**。`5.72/4.78 = +19.7%` 这个数
看起来越过了 +15% 门，但它是跨口径算出来的，**不成立**。同口径唯一
可比的是 **5.72/5.26 = +8.7%**。

### 8.2 门

| 设计图表述 | 折算所需 | 实测 | 判定 |
|---|---:|---:|---|
| §0.2 "≥6.0 TF/s" | 976.5 ms | 1024.3 | ❌ 差 47.8 ms |
| §2.3 "≥+15%" | 968.4 ms | 1024.3 | ❌ 差 55.9 ms |
| §2.3 括注 "4.78→5.5+"（字面 5.50） | 5.50 TF/s | **5.72** | ✅ |

三行互不一致（+15% 其实是 5.50，而 §0.2 要 6.0）。**本报告按严格口径
记作未达**：宁可把门槛说严，不拿括注的宽松读法给自己过门。

### 8.3 这条路线的理论终点

- T1 的 Q 残余 = 1024.3 − 978.3 = **46.0 ms**；
- 即使 Q 完全免费（物理上不可能），终点是 **978.3 ms = 5.99 TF/s**，
  **仍差 1 ms 到 6.05**。

也就是说：**"Q 复用"这条路线最多把我带到 6.0 门口，进不去。**
要真正越过 6.05，必须同时动 PV/staging 那段（651 ms 的地板成分）。
这不是本轮任务失败的借口，是下一轮立项的边界条件。

### 9.1 生产页面几何逐位门（新增）

先前 256 例门用 block 16/32/48/800，生产实际是 **832**。补 28 例
（ctx 16k–131k × m 1/2/7/7488，含页边界角点）：
**旧 vs 新 28/28 md5 完全相同**，两者对 fp32 参考最差 7.6e-08。

### 9.2 纠正一个无效判据

先前用服务 parity md5 判"全同"——**那个判据无效**：服务启动参数
`--override-generation-config {"temperature":0.7}` 会覆盖请求里的
`temperature:0`，实际是采样，md5 相同只是巧合。

改用 `logprobs`（3 prompt × 32 token）后：

| 对比 | 不同位置 | 最大偏移 | token 不一致 |
|---|---|---|---|
| 旧内核 boot1 vs 旧内核 boot2 | 24/96 | 1.21e-02 nat | 0 |
| **旧内核 boot2 vs 新内核** | **0/96** | **0** | 0 |

**那点偏移是"同内核不同次启动"的基线抖动，不是本次改动引入的。**
新内核与旧内核第二次启动逐位相同。

### 9.3 应用后实测

| ctx | 应用前 | 应用后 | 变化 |
|---:|---:|---:|---:|
| 8192 | 9.76 s | 9.82 s | +0.6% |
| 32768 | 46.31 s | 45.68 s | −1.4% |
| 131072 | 293.34 s | **278.15 s** | **−5.2%** |

与 WP3 的 A/B 结论一致。

### 9.4 仍未达的算力门

应用的是"服务级全绿、数值逐位同"的那一版，**不是**因为它达到了
6.0 TF/s——它没有（5.72 TF/s）。应用理由是可测量的端到端收益
（131k −5.2%）与零数值风险，而不是算力门达标。
