## 0. 三句话结论

1. **sdot4 QK 的"M>1 失败"不是 Q 行映射 bug**，S73/S74 的嫌疑点归错了。
   真正原因是**双缓冲的同步不足**：每 tile 只做一次 `__syncthreads()`，
   写侧会覆盖别人还在读的 buffer。补上首个屏障后大面积 NaN 消失，但仍有
   残余错误 → **第二处缺陷未定位，按止损条款本轮不采纳，不做计时**。
2. **MIN_CTX 降到 8k 的内核前提成立**：把门槛会首次踩到的 57 个小上下文
   角点全部测了，**逐位相同（max|d| = 0）**，S77 登记的"1-tile segment
   误差 0.08–1.0"在本次矩阵里**没有复现**。
3. **prefill 各阶段速度已测**（生产态，131k 冷缓存）：TTFT 279.2 s，
   19 个 chunk。**注意力占 57.7%、权重 GEMM 占 29.5%、通信 3.7%**，
   与 S78 的分解一致；注意力效率随深度从 6.7 掉到 5.9 TF/s。

## 1. WP1：sdot4 根因（详见 `.s79/wp1-sdot4-rootcause.md`）

### 1.1 排除"读错 Q 行"

把 3 个 token 的 Q 设成**完全相同的一行**再去跑：如果 bug 是"读到别的
pair 的 Q"，同 Q 下必然正确。实测**错误照旧**，而且两次运行**失败的行
不同**（一次 row1 h0/h1，一次 row1 h2/h3），`sexp` 在 1.0 / 3.0 / 正常值
之间跳。

→ 这是**不确定的内存竞争**，不是索引映射。

### 1.2 控制臂证明测试脚手架是干净的

用同一套 one-hot-V 脚手架跑**生产 fp16 内核**（同样 M=3、2 个 CTA）：
18 行全部在 `1e-5` 量级，`max|d| ≈ 3e-5`。

→ 脚手架、`reduce_segments`、KV 打包、host 参考都对，责任在 sdot4 内核。

### 1.3 差异定位到屏障

| 内核 | 每 tile 屏障 | 顺序 |
|---|---:|---|
| 生产 T1（fp16） | **2** | `sync; store(next); sync;` |
| sdot4 变体 | **1** | `store(next); sync;` |

双缓冲下 `nxt(j+1)` 与 `cur(j+2)` 是同一块。单屏障时，跑得快的线程在
第 j+2 轮开头就覆盖了慢线程第 j 轮还在读的 buffer。

### 1.4 修一处不够

`.s79/arms/attnd_inner.sdot4_fix1.hip`（补计算前屏障）后：
M=1 ✅；M=2 的 12 行里 10 行转绿，坏行从"大面积 NaN"变成"确定的数值错"；
M=2 仍有 2 行错 ~1.4e2。**第二处未定位**，按施工图 WP1 止损停止。

### 1.5 静态账（对设计图的两处勘误）

| 内核 | vgpr | spill | LDS |
|---|---:|---:|---:|
| 生产 T1（b93db390） | 120/121 | 0 | 32768 |
| sdot4 变体 | **109/110** | 0 | 32768 |
| sdot4 fix1 | 109/110 | 0 | 32768 |

- 设计图 HB2 担心"vgpr 只剩 0–1 个余量"**不成立**：sdot4 比生产基线
  **省 11 个 vgpr**；
- S73 台账的"104/105"与本轮 109/110 不符（编译选项差异），以本轮为准。

## 2. WP5：MIN_CTX 8k 角点（前置硬门）

门槛 16384→8192 后，chunk1 的形状会首次落进 `ctx ∈ [8192, 24576]`。
按 dispatch 实际的 `num_segments=4`，跑了
`ctx ∈ {8192,12288,16384,20480,32768} × q ∈ {1,2,7,7488} × block ∈ {16,32,800}`
共 **57 个用例**，对 fp32 参考：

**57/57 全部 `max|d| = 0.00000`（逐位相同）。**

原始数据：`runs/prefill-lctx/s79/wp5_corner.json`，脚本 `.s79/wp5_corner.py`。

读法：
- 门槛降到 8k **不会**把小上下文推进数值风险区，S77 §5 登记的"每 segment
  只有 1 个 tile 时误差 0.08–1.0"在本矩阵中没有出现（57 个角点里本来就
  含 1-tile segment 的形状）——这条注销，或至少不能作为阻断理由；
- 因此 WP5.2 的服务级 A/B 只是收益问题，不是正确性问题；本轮**未做**
  env 固化（服务级 A/B 需要一个完整停服窗口，本轮时间用在主线根因上）。

## 4. 出口裁决

| 工作包 | 门 | 结果 | 裁决 |
|---|---|---|---|
| WP1 sdot4 正确性 | bit-exact + KL ≤1% | 未过（补一处屏障后仍 2 行错） | **不采纳**，落排除表 |
| WP2 sdot4 计时 | 131k ≥+3% | 未做（正确性未过，按纪律不计时） | — |
| WP3 decode 三臂 | TPOT ≤−3% | 未做（依赖 WP1） | — |
| WP4 服务收账 | §6 全绿 | 未做（依赖 WP1） | — |
| WP5 角点（前置门） | 57 用例逐位同 | **57/57 max\|d\|=0** | 通过，服务级 A/B 待独立窗口 |
| WP6 散钱审计 | 账面闭合 | 尾 chunk 3776 仍拆 2496+1280 复现 | 落账，未施工 |

**本轮净产出**：把 sdot4 的失败从"神秘的行映射 bug"变成**已定位的同步
缺陷**（一处已修、一处待查），把 MIN_CTX 8k 的正确性前提**证成**，
并给出生产态 prefill 全阶段实测。按设计图出口 C 的一半收口：
`sdot4` 形态本轮不采纳，`v_dot4` 闭案取决于第二处缺陷能否在两轮内收敛。
