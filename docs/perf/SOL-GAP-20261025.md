# 与天花板基线逐块对比：116.4 ms 差在哪（2026-10-25）

> **问题**：`docs/perf/SOL-MEASURED-20261025.md` 给的可达天花板是 **29.3 ms / 97 t/s**
> （7.5k ctx、k=7、acc 2.84 口径），当前采纳配方 graph-A 实测 **116.4 ms / 24.87 t/s**。
> 差 3.9×——这 87.1 ms 具体差在哪些块上，哪部分是工程欠账，哪部分是基线本身够不着？
> **口径**：单请求、7469-token 真实文档、DFlash2 k=7（verify M=8）、TP=4、MBT 8192、
> graph-A（`docs/result/z100-five-phase-profile.md`），kernel 普查来自
> `/mnt/game/s27-prof/s27five3_rank0.1792854499912000168.pt.trace.json.gz`（20 稳态 round）。
> **前置**：先读 `docs/perf/ATTN-OPT-20261025.md`（注意力块的归因与本文件互补）。

## 0. 先校准：天花板基线有三处假设在当前工作点不成立

| # | 基线假设 | 实测现状 | 后果 |
|---|---|---|---|
| 1 | 权重 16.3 ms = 6.75 GB @ **414 GB/s（M=1 stream GEMV）** | 本工作点每 round verify M=8：5.47 GB 只跑出 **102 GB/s** 有效（53.4 ms）。P0 已证 M=8 生产 fp8 撞 LDS 读墙：冷态最好 163 GB/s（gateup），down 服务内热 L2 295 GB/s | M=8 的诚实地板 ≈ **30 ms**，不是 16.3；差 16 ms 只能靠 W4/`v_dot8` 打破 |
| 2 | AR 地板 12.6 ms（90 µs/op × 140，独立 `dist.all_reduce` 实测） | graph-A 服务内 **64.7 µs/op**（`ncclDevKernel_Generic_4` ×128）+ draft AR 1.2 = **9.5 ms**，已比假设地板好 3.1 ms | AR 这一项**已经"超标完成"**，不再是没有空间的第一大项；SOL 文档结论 3 需要按 graph 臂改写 |
| 3 | 29.3 ms 的分母记了 acc 2.84（承认投机红利），但**没有 draft 成本项** | k=7 的 draft 每 round 固有 **33.8 ms**（154 个 kernel），这是换 2.89 tok/round 的代价 | 天花板的 97 t/s 同时占了"accept 的便宜"和"没付 draft 的钱"，两头都偏乐观 |

结论：**29.3 ms 是 M=1 带宽 + 零 draft 的"纯 decode 天花板"，套在 k=7/M=8 工作点上要重新标定。**

## 2. 两个口径的判读

**按 round**：116.4 vs 29.3 = 3.9×；拆开是
**116.4 / 68（诚实地板）= 1.7× 工程欠账** × **68 / 29.3 = 2.3× 基线乐观**。
即"差距的一半是还没做完的工程，另一半是这条基线在本工作点本来就达不到"。

**按 token**（投机解码的公平口径，acc 2.89）：

| | ms/tok | t/s |
|---|---:|---:|
| SOL 天花板（29.3，acc 2.84） | 10.3 | 97 |
| 诚实地板（~68） | ~23.5 | **~42** |
| 现状 graph-A（116.4） | 40.3 | **24.87** |

逐块的每 token 成本（现状）：draft 11.7 + 权重 18.5（53.4/2.89）+ AR 3.3 + FA attn 2.9
+ lm_head/尾/杂 3.9。对照 M=1 纯 decode 的理论构成（权重 16.3 + AR 9.1 + attn ~4 + 杂 ~3 ≈
32 ms/tok）：**投机解码在权重项上按 token 已经便宜（18.5 vs 16.3 的前提是 M=8 带宽不塌——现在塌了，
塌掉的部分正好吃掉了 AR/attn 上省的）**；净输在 draft 11.7 ms/tok。

## 3. 对施工优先级的修正（相对 ATTN doc）

1. **draft 从"注意力之外"升为与权重并列第一**：33.8 ms、可收 16–22 ms，且完全没被微测过。
   第一步不是写代码，是补一次 **M=7 draft 形状的 kernel 级扫描**（31 次 434 µs 的 matmul、
   2 次 2461 µs 的大 matmul、1.23 ms 的 attn 2D、5.5 ms 的 lm_head，各自的 bytes/带宽算出来，
   与 ba/down 同款判据）。在扫描结果出来前，任何"draft 优化"都是猜。
2. **权重块（可收 ~22 ms）**：A1（ba，−8.5）照做；fp8 GEMM 组的 13 ms 是
   "从 102 GB/s 磨到 163 GB/s"的收益，**到 163 就到顶**（LDS 墙），别指望回到 16.3——
   那 8–16 ms 的剩余只响应 W4/`v_dot8`（独立立项）。
3. **FA attn（−4.1）**：BM16 过 parity 板即收，不变。
4. **AR：不再投入**。已低于基线地板，custom AR/RCCL 调参全部继续判死。
5. **天量剩余（42–46 ms）的出口只有三个，全在 k=7/M=8 结构里**：
   W4 打 LDS 墙、accept 再升（draft 质量或 dynamic-k 换手）、**c=4 并发摊薄**
   （SOL 文档自己的 c=4 行：54.4 ms / 209 t/s——权重一次读取喂 4 个请求，
   P0 文档 P4 的"红利在 4–5 路并发"同一结论）。

## 5. 单请求口径的执行路线（c=1 only，2026-10-25 追记）

约束变化：**并发摊薄出口关闭** ⇒ §3 里 42–46 ms 结构性剩余的出口只剩 **W4** 与 **accept** 两个；

AR 已优、不再投入。单请求的 t/s 恒等式只有一条：**t/s = accept / round_ms**，
