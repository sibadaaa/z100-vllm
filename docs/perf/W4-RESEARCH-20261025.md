# W4/`v_dot8_i32_i4` 调研：M=8 LDS 墙的唯一破法（2026-10-25）

> **问题**：verify M=8 的 fp8 权重读取被 LDS 读墙锁死在 ~163 GB/s（`docs/perf/GEMV-OPT-20261025.md`
> §4：每 1 B 权重要 21 B LDS 流量——A 按 fp16 对读放大 2× + LUT + scale）。墙内已收干
> （P0/P1/P2），**要再往下只有把每字节的点积密度提高**。本文回答：gfx906 上 W4 是否可行、
> 收益模型、已有资产、质量门禁与工作量。
> **性质**：调研 + 立项建议，不含代码改动。

## 0. 结论

1. **ISA 支持**：gfx906 原生 `v_dot4_i32_i8`（8×int8 点积，已在产线验证——`w8a8_sdot4_gemm`
   就是它，S11l/S11m）与 `v_dot8_i32_i4`（32 b 寄存器装 8 个 4-bit 权重）。fp8 需要的那套
   LUT/加宽机制在 int4/int8 上**全部消失**——dot 指令原生消费 int8 激活 × 打包权重。
2. **已有实测上限**：S24 L7 探针在生产 prefill 形状上测得 int8 sdot4 路线 **20.98–23.33 TF/s**
   vs fp8-emu 8.0–8.9 TF/s（**2.6× 计算余量**），合成数据相对误差 0.0002
   （`.s24/w2/L7/sdot4-probe.json`）。prefill 不是我们的目标，但它证明了 dot4 数据通路的效率。
3. **decode 收益模型（M=8，待探针验证）**：
   - fp8 现网：每 1 B 权重 ≈ 21 B LDS → 有效 163 GB/s；
   - W8A8 sdot4：A 是 int8（1 B/权重），LUT 归零 → ≈ 10–11 B/B → **~300 GB/s** 档；
   - **W4 + dot8**：权重字节减半 + 每 W 字节只有 2 B A(int8) → ≈ 4–5 B/原 fp8 字节
     → **600–700 GB/s 档**（对照：fp16 探针在 8.5 B/B 实测 451 GB/s）。
   - 换算到 step：权重项（fp8 GEMM 组 24.7 ms 诚实地板）→ W8A8 ~14 ms → **W4 ~8–10 ms**，
     即 round 再省 **~10–15 ms**。
4. **代价（不可回避）**：权重重新离线量化为 W4（per-group scale，group 64/128），
   **greedy 输出会变**（S11l/S11m 对 int8 已有定论；W4 更大）——必须走 parity 例外 +
   模型评测门禁。这是"更快但改数值"类的最大一次，需要显式拍板。
5. **建议**：立项，分三步走（§4），先花半天做 W4 GEMV 探针（复用 `tools/dcu/gemv_probe.cpp`
   的框架，dot8 内循环 + 打包 W4），拿到实测 GB/s 再决定全量量化投入。

## 1. 机制：为什么 fp8 路线有 21 B/B 的墙，而 W4 没有

现网 fp8-emu stream kernel（`csrc/rocm/fp8_emu_gemm.cu`）的每 chunk（16 B = 16 个 fp8 权重）
LDS 流量（M=8）：

| 项 | 字节 | 说明 |
|---|---:|---|
| A 加宽 fp16 对 | 8 m × 32 B = 256 | fp8 不能直接 dot，先查 LUT 展开 fp16 |
| W LUT 展开 | 8×16 B | 每 m 重复 |
| scale 折叠 | 8×32 B | |
| **合计 / W 字节** | **~21 B/B** | HBM 读 1 B W 的 LDS 代价 |

W4 + `v_dot8_i32_i4`：一个 u32 装 8 个 4-bit 权重，激活 int8（`per_token_group_quant_8bit`
现成，trace 里已在跑），点积原生 int32 累加，最后乘 per-group scale：

| 项 | 每 m、每 32 权重 | 说明 |
|---|---:|---|
| A int8 | 32 B | 无 LUT、无加宽 |
| W 寄存器 | 8 B（HBM 字节减半） | |
| scale | 每 group 一次 | |
| **合计 / 原 fp8 字节** | **~4–5 B** | ≈ fp16 探针（8.5 B/B → 451 GB/s）的一半流量 |

## 3. 质量门禁（决定生死的一项）

1. **离线量化**：fp8 权重 → int4，per-group（64/128）symmetric scale，校准集建议
   用真实 7469-token 文档 + 长上下文混合（本仓库有现成请求样本）；
   工具可用 GPTQ/AWQ 离线跑一次，或先 hand-rolled per-group minmax 看损失量级。
2. **per-op 门禁**：W4 路线对 fp32 参考的误差预计比 fp8 大 1–2 个量级，
   判据改为**模型级**：8 prompt greedy 对拍（预期不同）+ `vllm bench` 质量回归
   （`tests/evals/` 或 `vllm bench serve` 的固定任务集），给出数值结论再裁决。
3. **parity 例外**：按 ATTN doc §3 的近平局协议不够——W4 是系统性数值变化，
   必须带模型评测（accept 长度不能掉：draft 的候选来自 target 分布，
   target 质量下降直接打 accept，**accept 是单请求 t/s 的分子**）。
4. **回滚**：kernel 挂在派发表 + env 门（同 P0 模式），.so 回滚即走回 fp8 路线；
   量化权重是旁路文件，不动原 checkpoint。

## 4. 分步计划

| 步 | 内容 | 产出判据 | 估时 |
|---|---|---|---|
| 1 | **W4 GEMV 探针**：`gemv_probe.cpp` 加 dot8 内循环（W4 打包 u32×8），N=8704/5120、K=5120、M=8，L2-flush | 实测 GB/s ≥ 450（模型下限）⇒ 继续；< 300 ⇒ 停 | 0.5 天 |
| 2 | **数值样张**：离线量化 gateup 一层，W4 kernel vs fp8 现网对拍，看单层输出误差分布 | 误差在预期量级、无 NaN/溢出路径 | 0.5 天 |
| 3 | **全量量化 + kernel 接入**：全模型 W4 权重文件 + stream kernel 变体 + 派发表/门禁 | pytest + per-op 对拍 | 2–3 天 |
| 4 | **服务级 A/B + 质量评测**：step p50（预期 −10~−15 ms）+ 评测集 + accept 对比 | 三者同窗口 5 reps；accept 不降 | 1 天 + 评测 |

**Go/No-Go**：步 1 的实测带宽与步 4 的 accept 是两个硬闸；任一不过就停在纸上。

## 5. 与其他路线的关系

- **W8A8（int8 sdot4）**：不需要重新量化权重精度等级的中间站（fp8→int8 误差更小），
  但权重字节不减半，收益 ~2×（→300 GB/s 档）小于 W4 的 ~4×。若 W4 质量门禁失败，
  W8A8 是退路，且两者共享全部 kernel 骨架。
- **draft 侧 fp8/int8 化**：draft 权重 1.7 GB/rank bf16，量化收益量级相同、风险更低
  （draft 只出候选，不直接决定输出分布——但会改候选集，同样要 accept 门禁）。
  可以作为 W4 的伴生项同一批量化。

## 6. 附录：步 1 探针实测（2026-10-25，S29 WP-D）——**No-Go**

`tools/dcu/gemv_probe.cpp` 新增 `w4_dot8` 变体（`.s23/probes/isa_gate.py` 确认
`v_dot8_i32_i4` 在 gfx906 编译产物中出现 480 次，PASS）。数据：
`docs/perf/data/w4-probe-20261025.json`。

**ISA 事实修正（本探针的首要产出）**：`v_dot8_i32_i4` 是 **8×i4 × 8×i4** 的
点积（两侧都是 4-bit nibble），**不是** int8 激活 × int4 权重——§0.3 的模型
建立在错误假设上。int8 激活必须拆成 hi/lo 两个 signed-nibble 视图
（`a = 16·(a>>4) + ((a&15)−8) + 8`），每条 W word 需要 2 条 dot8（H/L）加
1 条 sum-w dot8，M=8 时每 W 字节 ≈ 4.25 条 dot8。

**实测**（N∈{5120,8704}、K=5120、M=8、L2-flush、30 iters；与现网服务并行
跑，in-run fp16 lds_m8 参照 388–418 GB/s，即 ~10% 环境折损）：

| 配置（最好） | raw nibble GB/s | **fp8-equivalent GB/s** |
|---|---:|---:|
| ROWS=8 NWARP=8 SLICE=1024 G=128（N=8704） | 27 | **54** |

数值核对：rel_l2 = 0（整数精确，scale=1；脉冲测试 m0n0=1、m1n0=−127 精确）。

**判定：STOP（No-Go）**。54 GB/s(fp8-eq) 距 go 闸 450 差 8×，也低于 fp8
现网 163 GB/s。结构性上界：即使零开销的 2 dot8/W 字节版本，按实测单指令
速率外推也只有 ~100–115 GB/s(fp8-eq)——§0.3 的 600–700 GB/s 档在 gfx906
上不可达。**W4 立项停在步 1，不投入量化**；dot 路线只剩 W8A8 sdot4
（`v_dot4_i32_i8`，int8 激活直接可用）一条，且模型预期也只有 ~300 GB/s 档。
