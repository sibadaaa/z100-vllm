# 后续优化路线（2026-10-27）

> **输入**：S34 终局数据（已汇总在 [现状](STATUS-20261027.md)）、
> S35 MoE 设计/施工图、S33/S32 账本。
> **排序原则**：按“可回收的绝对 ms/token”排，不按百分比；先确认墙位再写内核；
> 改模型输出的项必须过 eval + 贪心 diff 板 + 用户裁决；每 WP 独立可回滚。
> **当前基线**：7.5k c=1 46.5 ms/步 / 2.40 tok/步 / 51.6 t/s；128k 31.4 t/s；
> c=4 聚合 59–70 t/s；生产 60k 均值 32.8 t/s。

## 1. P0：Qwen3.8-27B 稠密侧（按顺序做）

### R1. batch-1 长扫 attention：split-KV / 分段重扫

- **靶子**：128k 时 16 层全注意力按 `(seq, kv-head)` 切分，TP4 后每卡只有
  1 seq × 1 kv-head 的工作可切；步时从 46.5 涨到 62.2 ms，其中 ~2/3 是并行度。
- **做法**：按 ctx 自适应 split-KV（段间归约复用 `reduce_segments`），
  或把 `BLOCK_M`/segment 数与 ctx 绑定；`VLLM_GFX906_ATTN_DECODE_SEGMENTS`
  钩子已存在。7.5k 的“无过门增益”（S33-WP4）不能外推到 128k。
- **预期**：128k 31.4 → **36–39 t/s**（step −10–15%）；7.5k 不回归。
- **门**：128k step p50 −10%；7.5k/32k 回退 ≤2%；零翻转或按 S29-BM16 的
  “无翻位值漂移”口径披露；长跑 30 min。
- **风险**：改累加序 → 贪心流；分段数增加 → launch/归约开销。
- **依据**：[`STATUS`](STATUS-20261027.md) §3.2、
  [`z100-s33-fp8-scope-design.md`](../design/z100/archive/z100-s33-fp8-scope-design.md) D5。

### R2. F1：c=4 合批 verify 效率

- **靶子**：c4 聚合只有单流的 1.2–1.4×；每流从 48.6 掉到 16–18 t/s。
  120 KiB verify 载荷已走 push AR，所以问题不在通信，而在 verify 形状的
  内核/调度（12 token 的批与捕获尺寸 [1,2,4] 的匹配需核查）。
- **做法**：先 profile c4 的 verify 段（kernel 分账 + 步内空隙；profile collect
  会 wedge 服务，采完立即重启），再决定：verify 形状专用 tile、把 4 流拆成
  更小的 verify 批、或扩捕获尺寸。不要先改 AR。
- **预期**：c4 聚合 **75–85 t/s**（+20–30%），单流不回归。
- **门**：c4 step p50 −15%；单流 step ±2%；accept 不掉；长跑 30 min。
- **依据**：[`STATUS`](STATUS-20261027.md) §2.3 / §5-R2；
  S34-WP3 的结论已并入 STATUS。

### R3. rms_norm / quant 融合进 push AR 核

- **靶子**：S33 分账的真实核间空隙 3.8 ms/步（~1000 处 × 5 µs），
  其中 AR 出口紧接 add-rmsnorm / quant；push AR 已采纳，融合落点解锁。
- **做法**：`cross_device_reduce_push` 归约出口就地做 add-rmsnorm（MLP 侧
  再加 fp8 quant）；归约序不变，norm 的 rsqrt 行内归约需单独核位同。
- **预期**：e2e **−0.8 ~ −1.4 ms/步**（per-op −20% 口径）。
- **门**：微测 per-op −20%；e2e −0.8 ms；T=1/T=4 数值对拍；
  `cmp_capture` 零翻转（nospec）或 in-session 位同（MTP）。
- **成本**：csrc 重编译（`_C_stable_libtorch`），设计+施工图已就绪。
- **依据**：[`z100-s34-wp4-ar-fusion.md`](../design/z100/s34/z100-s34-wp4-ar-fusion.md)。

### R4. fp8 GEMV split-K

- **靶子**：whole-A 两变体卡在 qkv 402 / o 361 / gdn_out 364 GB/s
  （<450 门），换算法类才有机会过 450。
- **做法**：K 维切 S 段、固定段序两段式归约（partial → reduce），
  禁止 atomics 无序累加；先 M=1，再 M=3。
- **预期**：e2e **−1.5 ms/步**（门），形状带宽 ≥450 GB/s。
- **门**：六形状 × M∈{1,3} 微测；e2e −1.5 ms；零翻转硬门；
  env `VLLM_DCU_FP8_GEMV_SPLITK=1` 默认关。
- **风险**：第二次 launch 落在 ~1000 处核间空隙敏感区；若 e2e 不升反降，
  先并 partial-reduce 进 push AR 空闲波（与 R3 协同）。
- **依据**：[`z100-s34-wp5-splitk-gemv.md`](../design/z100/s34/z100-s34-wp5-splitk-gemv.md)。

### R5. INT8 sdot4 W8A8（约束外，收益最大）

- **靶子**：现役 fp8 emu GEMV 256 × 48.8 µs ≈ 12.5 ms/步（~40%）；
  `v_dot4_i32_i8` 原生 3.9× → GEMV ~3.2 ms，**step −9 ms 级**。
- **前提**：`Qwen3.8-27B-Channel-INT8-w8a8` checkpoint 已在机器上（29 GB），
  MTP 层已量化；但**会改贪心输出**（S11l/S11m 已定论），必须 eval。
- **做法**：`launch_arm.py` 支持模型路径覆盖 → 起 INT8 臂 → 7.5k/60k 探针 →
  贪心 diff 板（首分歧/偏移）→ `tests/evals/` 或固定任务集评测 → 用户裁决。
- **预期**：7.5k 49.4 → **40.4 ms/步**（ms/tok 20.6 → 16.7，**+23%**）；
  KV 池不变（int8 与 fp8 同为 1 B/参数）。
- **门**：质量评测通过（阈值由用户定，建议退化 ≤0.5%）+ accept 不显著掉 +
  长跑；失败即回 FP8。
- **依据**：[`z100-s34-wp7-int8-ab.md`](../design/z100/s34/z100-s34-wp7-int8-ab.md)。

## 2. P1：精度与调度（有收益，但要 eval / 裁决）

| ID | 路线 | 机制 | 预期 | 门 / 风险 |
|---|---|---|---|---|
| R6 | w4a16 MLP（低风险变体） | 只量化 gateup+down（4.28/5.58 GB），attention/GDN 保 fp8 | −3.8 ~ −4.3 ms/步 | eval + 贪心 diff；**不要走 `v_dot8`**（W4 探针 No-Go） |
| R7 | lm_head fp8 / W8A16 | 636 → 318 MB | −0.45 ms/步 | 改 top-1 分布；单独裁决 |
| R8 | KV fp8 + 核内 LUT | 7.5k 收益小，长 ctx 线性放大 | −0.15 ~ −0.25 ms @7.5k | 先证伪“反量化未融合”（历史 ITL +41%）；优先级低 |
| R9 | SSM state fp16 | 36.9 MB/seq 读写 | −0.15 ~ −0.2 ms | 漂移风险真实；最后做 |
| R10 | 自适应投机 / TTFT | 按预期输出长度决定是否开 MTP；或缩短 draft 预填充 | 短请求墙钟 +30%（关 MTP）；盈亏平衡 220–230 → 100 token | 新增建议，未立项；策略层 0.5–1 天 |
| R11 | dynk 按 k=2 重标定 | `dynk_ema_good=5.0` 是 k=7 遗留；k=2 建议 ~1.2 | 64k/128k t/s 可能 +1.5–3% | E 腿证明全 k 打平；只做阈值 A/B，不重写机制 |
| R12 | prefill / TTFT | 8k 840 t/s vs 1208 SOL；chunk 边界 337 ms；MBT 自适应 | TTFT −5–10% | 不要排 2× 预算；GEMM 已到 16.5–17.7 TF/s |

> **R10 的算法**：`N/51.6 + 2.40 = N/37.5 + 0.72` ⇒ 盈亏平衡 ≈ 230 token
> （用 36.9 t/s 则 ≈ 218）。
> 对 DSH/agent 这类“短回复多、长回复少”的负载，按 `max_tokens` 或
> 首 token 后预测长度关闭 MTP，可直接消掉 1.7 s 的 TTFT 惩罚；对长输出
> 保持 MTP。这是当前**单位工程量收益最高**的调度项之一。

## 3. S35 轨：MoE 架构适配（独立端口，不碰生产）

> 设计：[`z100-s35-moe-design.md`](../design/z100/s35/z100-s35-moe-design.md)；
> 施工：[`z100-s35-moe-construction.md`](../design/z100/s35/z100-s35-moe-construction.md)。
> **当前门禁**：生产占满 4 卡（VRAM 87%×4），**没有空闲卡**；S35-WP0 的
> 决策树会在“无空闲卡”处停并报告。需要用户给窗口，或接受 MoE 只在
> 生产停机/降载时跑。**不得 kill 生产服务。**

| WP | 内容 | 目标 | 判据 |
|---|---|---|---|
| WP0 | 卡分配 + 权重下载 | OLMoE 13.8 GB + Qwen3.6-35B-A3B-GGUF ~20 GB | 无空闲卡→停；sha256 全过 |
| WP1 | MoE 数值门禁 | `tests/kernels/test_gfx906_moe.py` | 全绿（误差/位同/无 aiter） |
| WP2 | Tier A OLMoE e2e | 本机首个 MoE 基线 | 正确性 + decode/TTFT（N≥2） |
| WP3 | Tier B 35B GGUF 复验 | 生产候选定案 | 正确性 + 基线 +（卡 2 对照） |
| WP4 | C++ MoE 内核 VGPR 审计 | 关闭 R1 | 全 ≤203 或锁定卡 0/1 |
| WP5 | 墙位鉴定 | 只测量 | 分账 ≥90% + 双域墙位 |
| WP6 | Triton 调优配置 | OLMoE +5% | e2e +5% 无回退 |
| WP7 | GGUF decode 内核 | **e2e decode +20%** | per-kernel 1.5× + 零翻转 + 长跑 |
| WP8 | GGUF prefill MMQ（条件） | TTFT +15% | 仅当 prefill 专家 GEMM >40% |
| WP9 | Qwen3-30B-A3B W8A16 TP=2（条件） | 投产判定数据 | WP4 过 + 用户拍板 |

**明确不做**：MoE + GPTQ-Int4/AWQ-4bit、GPT-OSS-20B（MXFP4）、Qwen3-235B、
aiter 后端、EP、MoE 上叠 MTP、MoE 多模态 mmproj、bf16 MoE 权重。

## 5. 排期与落点

### 5.1 建议顺序

| 阶段 | 内容 | 工作量 | 依赖 |
|---|---|---|---|
| P0（0.5 天） | 修 systemd 漂移；复测 c4-128k 探针；dynk 阈值 A/B | 0.5–1 天 | 无 |
| P1（1–2 周） | R1 长扫 attention（先微测/分段 A/B）；R2 F1 profile | 3–5 天 | 无 |
| P1（1–2 周） | R3 AR 融合；R4 split-K GEMV（设计已就绪） | 2–3 天/项 | csrc 构建窗口 |
| P2（1–2 周） | R5 INT8 A/B + eval；R10 自适应投机 | 2–4 天 | 用户裁决 / 评测集 |
| P3（按窗口） | R6/R7/R8/R9 精度项；R11 dynk / R12 prefill | 按裁决 | eval |
| 并行轨 | S35 MoE WP0–WP9 | 2–3 周 | **空闲卡窗口** |

### 5.2 预期落点（同口径，引擎 t/s）

| 里程碑 | 7.5k c=1 | 128k c=1 | c=4 聚合 | 置信度 |
|---|---:|---:|---:|---|
| 现状（s34-prod） | 51.6 | 31.4 | 59–70 | 实测 |
| +R3/R4（融合 + split-K） | 53–55 | 32–34 | 60–70 | 中 |
| +R1（长扫 attention） | 53–55 | **36–39** | 65–75 | 中 |
| +R2（F1） | 53–55 | 36–39 | **75–85** | 中低 |
| +R5（INT8，若裁决通过） | **60–64** | **40–43** | **85–100** | 低（需 eval） |

> 这些数不是承诺：R1/R2 的收益取决于 kernel 结构，R5 的收益取决于质量门。
> 每项仍按“微测 → 数值 → 服务 smoke → 同口径 e2e → 长跑”六步走。

### 5.3 需要用户拍板的事

1. **INT8 是否允许做质量评测**（R5；不改生产默认，只做 A/B + eval）。
2. **w4a16 / lm_head / KV 精度**是否进入下一轮（R6–R8）。
3. **MoE 轨的卡窗口**：是否接受在生产低峰停机 2–3 小时/次，或换卡。
4. **systemd 与手工臂**用哪条作为唯一事实来源（建议 systemd）。
5. 短请求是否接受“按长度自适应关 MTP”（R10）——这会改变尾延迟分布。
