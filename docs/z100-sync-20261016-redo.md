# Z100 正确 base 重做 sync（2026-10-17）

## 1. 为什么重做

上一次同步（`c2ade7b11`）的合成锚点把 **fork 自己的 tree** 当 merge base，
于是"上游 HEAD 也有同名文件"的路径全部被判成"本方未改动"而被上游整体覆盖，
fork 代码被静默丢弃：gfx906 C++ 内核、注意力调优层、Qwen3.5 的
`Qwen3_5GatedDeltaNet`、GGUF C++ 等都不在合并结果里。上一轮 10 个注意力测试
失败、GDN 测试连收集都失败，根因就在这里。

## 2. 这次怎么做

正确语义要求 base = **上游在上次同步点的 tree**：

| 角色 | 提交 | 内容 |
|---|---|---|
| base | `d99949dba` | 合成提交，tree 与上游 `b44895cf` **逐字节一致**（`0df6ef40ad4df46885bcbd1464b48af2d4ed46e8`） |
| ours | `805c5f2be` | 合成提交，tree = fork 的 `d40923054` |
| theirs | `bb7e8dae1` | 合成提交，tree = 上游 main `64175d38` |

`git merge-base ours theirs` 返回 base ✓。三类对象用 GitHub API + raw 下载
重建（base 侧只缺 97 个 blob，全部 SHA 校验通过）。

合并结果：**91 个显式冲突**（49 UU / 29 AA / 8 DU / 5 UD），全部人工解决，
无静默丢失。

## 4. 冲突解决要点

- **csrc（29 AA + 2 UU）**：上游已把 `csrc/libtorch_stable/*` 拍平回 `csrc/*`
  并改用 stable ABI。fork 的 `csrc/<同名>` 是"旧的自己那份"，因此 shared 文件
  一律取上游；fork 特有的内核留在独立 legacy `_C` 源文件里
  （`csrc/rocm/gfx906_layernorm_kernels.cu`、`csrc/rocm/gfx906_torch_bindings.cpp`、
  `csrc/quantization/gguf/gguf_{ops.h,torch_bindings.cpp}`、
  `csrc/mamba/gfx906_decode_kernels.cu`、`csrc/quantization/gguf/gguf_kernel.cu`）。
  例外（必须保留 fork 内容）：`csrc/quantization/gptq/compat.cuh` 的 DTK
  `atomicAdd(half2)` 探测、`csrc/fused_qknorm_rope_kernel.cu` 的 DTK
  `__syncwarp` 守卫、`csrc/rocm/ops.h`/`torch_bindings.cpp` 的 emu 算子。
- **requests/requirements（16 个文件）**：取上游版本（DTK 专用依赖在 `requirements/dcu.txt`）。
- **qwen3_5.py（11 块）**：保留 fork 的 GDN 类与 `load_weights`，视觉塔用上游的
  `input_norm=build_mm_input_norm(...)` 叠加 fork 的 `enable_multimodal` 判定。
- **qwen3_next / gdn_linear_attn**：vendored `Qwen3NextConfig` 已随上游删除，
  改从 `transformers` 导入。
- **gdn_attn.py**：上游新的 checkpoint builder 与 fork 交叉块不自洽，取上游整文件，
  仅保留一个值为 `None` 的 `non_spec_query_start_loc_cpu` 字段（gfx906 causal-conv
  回退自动退化为一次 DtoH 同步，不影响正确性）。
- **注意力 ops/backend**：成对取 fork 自洽版本（上游新内核签名与 fork 调优层的
  启动器不匹配，混用会 `NameError: use_per_token_head_scales`）。

| 套件 | 上一版（错误 base） | 本版 |

说明：
- `test_gdn_metadata_builder.py` 单独跑 62 全过；与其它文件混跑会因测试间共享状态
  互相污染（既有问题）。
- 3 个 GDN 失败是 fork 旧测试的桩（`SimpleNamespace`）缺上游新 builder 需要的
  `seq_lens_cpu_upper_bound` 等字段，属测试待更新。
- `test_causal_conv1d.py` 的 66 个失败与 port 树（merge 前部署状态）的基线同量级
  （上一轮对照：attention+causal_conv1d 合计 74 失败），非本次合并引入。
- 注意力内核测试与模型实跑仍会撞上 **DTK Triton 的 `PassManager::run failed`**
  （在 port 树/HEAD 两个版本上同样复现），属环境/工具链限制。
